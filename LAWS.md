# The Laws of esneiderbravo

> This is the constitution of this project. It does not restate the standards —
> it **binds** them. Every AI agent working in this repository MUST read this
> file at the start of a session and MUST comply with every standard it links
> below. When a standard conflicts with an agent's default behavior, the
> standard wins.

- **Project**: esneiderbravo — Esneider Bravo's GitHub profile README: the landing page rendered at github.com/esneiderbravo, with a daily GitHub Actions workflow that regenerates the GitHub-stats and top-language SVGs.
- **Organization**: Esneider Bravo (personal profile repository)
- **Stack**: Markdown + HTML profile README rendered by GitHub, self-hosted metric SVGs generated by the lowlighter/metrics GitHub Action, automated by a scheduled GitHub Actions workflow (cron). No application runtime, no build step, no package manifest.

## Binding rules

1. **Read the relevant standard before touching its area.** The table above is
   the map. Agents open the standard that governs the code they're changing.
2. **The standards are enforced, not advisory.** A violation is a blocking
   finding in review.
3. **Amendments go through the lawbook workflow.** A standard is changed like code — via a
   reviewed change (see the lawbook law). An agent may propose an amendment;
   it may never silently ignore a standard.
4. **Entry points reference the law.** [`CLAUDE.md`](CLAUDE.md) and
   [`AGENTS.md`](AGENTS.md) point every agent here first.

## Project-specific laws (profile repo)

1. **`main` is always live.** A push updates github.com/esneiderbravo
   immediately. Treat every change to `README.md` as an outward-facing publish —
   confirm before pushing.
2. **Generated assets are workflow-owned.** `metrics.base.svg` and
   `metrics.langs.svg` are regenerated by the Metrics Action; never hand-edit
   them.
3. **Brand tokens are law.** Teal `#0E8E8E` on near-black `#0B0F10`; teal→cyan
   gradients. New visual elements match the existing badge/card style and keep
   meaningful `alt` text.
4. **No secrets in the repo.** The metrics workflow authenticates only via the
   `METRICS_TOKEN` GitHub secret.
5. **Quality gates, restated for a content repo.** There is no application code,
   test runner, or build. "Gates" here = the README renders correctly on the
   profile and the Metrics workflow run is green.
