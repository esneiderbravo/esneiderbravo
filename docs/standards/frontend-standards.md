# Frontend / Presentation Standards — esneiderbravo

Rules for the profile's presentation. A law of the project — see
[`../../LAWS.md`](../../LAWS.md). Architecture and boundaries:
[`architecture.md`](architecture.md).

> **This repo has no application frontend** — no framework, components, routes,
> or client code. The "frontend" is the GitHub-rendered profile: `README.md`
> markup plus the assets and services it embeds. This standard governs that.

## Structure — strictly enforced

| Layer | Location | Responsibility |
|-------|----------|----------------|
| Content | `README.md` | Section structure, copy, and layout of the rendered profile |
| Committed assets | `metrics.base.svg`, `metrics.langs.svg` | Embedded by relative path; generated by the workflow, never hand-edited |
| Remote services | `README.md` `<img>` URLs | Themed cards/badges (shields.io, ghchart, capsule-render, readme-typing-svg, activity-graph, opengraph) |

- The README is the single source of truth for what the profile shows.
- Generated SVGs are referenced, never inlined or edited by hand.

## Rendering & markup boundaries

- Author for **GitHub-flavored Markdown as GitHub renders it** — the subset of
  HTML GitHub allows (`<div>`, `<img>`, `<table>`, `<sub>`, `<a>`, `align`).
  No `<script>`, no CSS files: styling rides on the remote service query params
  and the metrics workflow's `extras_css`.
- Keep the existing centered-`<div>` / `<table>` layout idiom; new sections read
  like their neighbors.

## Assets & data

- New visuals are either a committed `./metrics.*.svg` (produced by the workflow)
  or a themed remote badge/card service. Do not commit ad-hoc raster images when
  a themed service or generated SVG fits.
- Pin the metric SVGs by relative path so the profile renders from the repo, not
  a live third-party call, for the self-hosted stats.

## Brand & UI

- **Brand tokens are law**: teal `#0E8E8E` accents, near-black `#0B0F10` badge
  labels, teal→cyan (`0E8E8E`→`22c9c9`) gradients. No new palette colors.
- Badges follow the existing shields style (`style=for-the-badge` or
  `flat-square`, `labelColor=0B0F10`).
- Every `<img>` carries meaningful `alt` text — it is the profile's
  accessibility contract and its "documentation" (see
  [`documentation.md`](documentation.md)).

## Formatting, linting, docs

- No linter configured. Optional Markdown hygiene:
  `npx --yes markdownlint-cli2 "**/*.md"`.
- No i18n layer — the profile is authored directly in English (the tagline notes
  bilingual EN/ES working ability; the page copy itself is English).
